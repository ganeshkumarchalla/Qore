# Q# and Microsoft QDK in QORE

QORE compiles supported Q# source with Microsoft QDK, produces Base-profile QIR,
and translates the validated circuit to the existing Aer simulation and Forge
pipeline. The language adapter validates source before invoking the compiler.

Create or import a `.qs` file in Explorer. The editor provides Q# highlighting.
Run it from Studio or use `qsharp validate`, `qsharp run`, and `qsharp transpile`
in the command console. These actions operate on the active file.

```qsharp
namespace Bell {
    open Std.Intrinsic;
    open Std.Measurement;
    @EntryPoint()
    operation Main() : Result[] {
        use qs = Qubit[2];
        H(qs[0]);
        CX(qs[0], qs[1]);
        return MResetEachZ(qs);
    }
}
```

The ideal distribution is 50% `00` and 50% `11`; finite shot counts fluctuate.
QORE displays the state before terminal measurement/reset when providing Bloch
vectors and circuit analysis. This Bell pair has mixed single-qubit reduced
states, so its individual Bloch vectors have zero length.

## Installation

Use `python -m pip install ".[qdk,qiskit-tools,quantum-runtime]"` in the project
environment. The Docker build enables the QDK and Qiskit tools profile by default; a minimal
image can explicitly set `--build-arg QORE_QUANTUM_SDKS=false`.
`/api/capabilities` reports what the running server actually has installed.

## Supported scope

One static `Main()` operation, optional namespace and standard-library opens,
bounded qubit allocation, supported gates and adjoints, numeric rotation angles,
and terminal `M`, `MResetZ`, or `MResetEachZ` results are supported. Existing
source-size, qubit, operation, shot, timeout and Forge equivalence limits apply.
Helper operations, external Q# projects, loops, branches, adaptive algorithms,
Azure hardware submissions and arbitrary Python are outside this adapter.
Unsupported programs receive explicit errors. Installing QDK does not make every
Q# program executable through QORE's circuit adapter.

Saved `.qs` files use the `qsharp` workspace kind. The SQLite migration preserves
existing files, deleted entries, versions and workspace state.

Official SDK documentation: https://learn.microsoft.com/azure/quantum/

## QDK compatibility status

| Workflow | QORE status |
| --- | --- |
| Static single-file Q# circuits | Integrated; compiler, operator, measurement-order and API tests |
| Microsoft Base-profile QIR | Generated by the installed QDK compiler |
| Simulation and Forge | Validated circuit translated to Aer and QORE equivalence checks |
| Q# file editing and persistence | Integrated `.qs` files and database migration |
| General Q# helper operations and project manifests | Not integrated |
| Adaptive programs, branches and measurement-driven loops | Not integrated |
| Microsoft resource estimator | Not integrated |
| Azure Quantum targets and job lifecycle | Not connected; requires workspace identity, target configuration and explicit submission |
| Jupyter magics and Python orchestration | Not executed by the browser circuit adapter |

The QDK package's installed API surface is broader than QORE's execution
surface. A package import check is not evidence that a workflow is integrated.
General QDK execution needs a separate bounded worker with cancellation,
memory/time limits, project-file isolation and result schemas; adaptive programs
cannot be represented honestly as one static circuit or one unitary matrix.
Cloud execution additionally needs Azure configuration and provider-specific
target validation. Do not label these workflows supported until their complete
execution paths have integration tests.
